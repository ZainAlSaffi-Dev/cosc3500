Where the randomness went

There is no random number generator anywhere in this program.

The Feynman-Kac theorem says the average outcome of a random process solves a deterministic equation. Each source of noise became one term of that equation.

the noise in S became ½ v S² VSS

the noise in v became ½ ξ² v Vvv

their correlation became ρ ξ v S VSv

Every job stamps its own provenance into its results. The jobs run on a reserved compute node, pinned to one machine, with five repetitions, and the tests re-pass before every sweep.

The belief that died

The solver was assumed to be memory-bound. It is not. Optimisation moved it from division-bound to compute-bound.

Benchmarking

The page-size discovery

solver4 KiB pages2 MiB pages from pages alone
baseline44.8 52.61.17 times
level 280.0 131.21.64 times
level 681.1 134.81.66 times

Million cell updates per second, same binary, same node. Sixteen mebibytes is eight huge pages or four thousand small ones, against a translation buffer with a thousand entries. It was found because the median of five repetitions was quietly averaging two different memory regimes.

Reflection

Four questions the spec asks

  • The main conclusion. At this optimisation level the compiler has already done the textbook transformations, so the hand optimisations that pay are the ones it is forbidden to do.
  • The biggest surprise. Page size was worth more than five of the six techniques put together, and it is not a code change at all.
  • What I would do differently. Reserve the node exclusively from the very first job. An early shared-node measurement was real, but it answered a different question than the one I asked.
  • Milestone 2. The roofline says the kernel is now compute-bound, so the next win is doing more arithmetic per instruction, which is exactly what SIMD is. Then OpenMP across rows, which needs no locking because the two-buffer design makes every cell independent within a step.
